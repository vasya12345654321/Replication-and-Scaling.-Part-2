# Задание 1

## 1. Активный master-сервер и пассивный репликационный slave-сервер

В данной архитектуре один сервер (Master) является основным и принимает все операции чтения и записи. Второй сервер (Slave) является резервным и получает копию данных посредством репликации.

### Преимущества

- повышение отказоустойчивости;
- наличие резервной копии данных;
- быстрое восстановление после выхода Master из строя;
- возможность выполнять резервное копирование без нагрузки на основной сервер;
- простота настройки и обслуживания.

### Недостатки

- запись данных выполняется только на Master;
- возможна небольшая задержка синхронизации данных.

---

## 2. Master-сервер и несколько Slave-серверов

В данной архитектуре один сервер принимает все операции записи, а несколько Slave-серверов обслуживают запросы на чтение.

### Преимущества

- увеличение производительности чтения;
- распределение нагрузки между несколькими серверами;
- возможность обслуживать большое количество пользователей;
- повышение отказоустойчивости;
- возможность масштабирования системы без изменения приложения.

### Недостатки

- запись данных остается только на Master;
- при большом количестве операций записи Master может стать узким местом.

## Вертикальный шардинг

Вертикальный шардинг представляет собой разделение одной таблицы по столбцам. Каждая новая таблица содержит одинаковое количество строк, но только необходимые ей столбцы.

### Исходная таблица

| id | name | email | password | phone |
|----|------|--------|----------|--------|

---

После разделения получаем:

### Сервер №1

**База данных USERS**

| id | name | email |
|----|------|--------|

---

### Сервер №2

**База данных SECURITY**

| id | password |
|----|----------|

---

### Сервер №3

**База данных CONTACTS**

| id | phone |
|----|--------|

### Принцип работы

После получения запроса приложение обращается к необходимой базе данных:

- данные пользователя — USERS;
- пароль — SECURITY;
- телефон — CONTACTS.

## Горизонтальный шардинг

При горизонтальном шардинге таблица users разделяется по диапазону идентификаторов.

### Users Shard 1

id = 1–100000

---

### Users Shard 2

id = 100001–200000

---

### Users Shard 3

id = 200001–300000

Все таблицы имеют одинаковую структуру, но содержат разные строки.

### Принцип работы

Перед выполнением запроса приложение определяет диапазон ID пользователя и направляет запрос в соответствующий шард.

## SQL

```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(100),
    password VARCHAR(255),
    phone VARCHAR(20)
);
```

### Первый шард

```sql
CHECK (id BETWEEN 1 AND 100000)
```

### Второй шард

```sql
CHECK (id BETWEEN 100001 AND 200000)
```

### Третий шард

```sql
CHECK (id >= 200001)
```
